# MikuToYou UI -> 移动端开发映射（V1）

## 1. 目标

将 `docs/ui/ui-mockup.html` 与 `docs/ui/UI规范.md` 映射为可直接实现的 React Native 客户端结构（纯客户端、无后端）。

> 说明：`ui-mockup.html` 仅作为视觉稿参考，实际开发以 RN 组件和样式为准。

## 3. 页面与组件映射

## 3.1 ChatScreen（聊天）

- 对应 UI：聊天页主屏。
- 组合组件：
  - `TopBar`（标题 + API 状态点）
  - `Live2DPanel`（模型区域/失败占位）
  - `MessageList`（`FlatList` 消息流）
  - `Composer`（输入 + 发送）
  - `EmptyState`（未配置 API 时展示）
- 关键逻辑：
  - 读取 `appSettings`，若缺 `apiBaseUrl`/`apiKey`，展示引导。
  - `onSend` 调用 `llmClient.sendMessage()`，处理 loading/error。

## 3.2 SettingsScreen（设置）

- 对应 UI：设置页。
- 组合组件：
  - `TopBar`
  - `SettingsForm`（字段校验 + 保存）
  - `Toast`（保存结果提示）
  - `ConfirmDialog`（清空聊天确认）
- 关键逻辑：
  - 表单数据保存到 `AsyncStorage`。
  - “测试连接”调用 `llmClient.testConnection()`。
  - “清空聊天记录”调用 `useChatStore.clear()`。

## 3.3 RootTabs（底部导航）

- 使用 `@react-navigation/bottom-tabs`。
- 仅两个 Tab：
  - `聊天` -> `ChatScreen`
  - `设置` -> `SettingsScreen`

## 4. Live2D 在 RN 的实现映射

RN 里建议用 `react-native-webview` 承载 Live2D（MVP 成本最低）：

- `Live2DPanel` 内置 `WebView`。
- 加载本地 `assets/live2d/index.html`（其中接入 pixi + live2d runtime）。
- RN 与 WebView 通信：
  - RN -> WebView：切换模型、重试加载。
  - WebView -> RN：加载成功/失败事件上报。

这样可以保留“纯客户端”特性，同时规避 RN 直接渲染 Live2D 的高复杂度。

## 5. 类型定义映射（TypeScript）

```ts
// types/settings.ts
export interface AppSettings {
  apiBaseUrl: string;
  apiKey: string;
  model: string;

// types/chat.ts
export type ChatRole = "user" | "assistant" | "system" | "error";

export interface ChatMessage {
  id: string;
  role: ChatRole;
  content: string;
  timestamp: number;
}

// types/ui.ts
export interface UiState {
  sending: boolean;
  toast?: { type: "success" | "error"; text: string };
}
```

## 6. 状态与存储映射

- `useAppSettings`
  - `settings`
  - `saveSettings(payload)`
  - `loadSettings()`
- `useChatStore`
  - `messages`
  - `appendMessage(msg)`
  - `clear()`
- `useUiStore`
  - `sending`
  - `setToast()`

存储实现统一落在 `services/storage.ts`（基于 `@react-native-async-storage/async-storage`）。

## 7. 服务层映射

## 7.1 llmClient.ts

- `sendMessage(settings, messages, userInput)`：
  - 前端直连 API（OpenAI 兼容格式）。
  - 返回 assistant 文本。
- `testConnection(settings)`：
  - 发送最小请求验证可用性。

## 7.2 live2dBridge.ts

- `buildLive2DHtml(modelUrl)`：生成 WebView 加载内容（或加载本地 html）。
- `postToLive2D(webviewRef, event)`：向 WebView 发送控制消息。
- 处理 `onMessage`，解析加载成功/失败事件。

## 8. 样式映射（RN）

将 `UI规范` token 映射到 `theme/tokens.ts`：

- `colorPrimary: "#39C5BB"`
- `colorBg: "#0B1220"`
- `colorPanel: "rgba(255,255,255,0.08)"`
- `radiusMd: 12`
- `radiusLg: 16`
- `space: { xs: 8, sm: 12, md: 16, lg: 24, xl: 32 }`

## 9. MVP 开发顺序（移动端）

1. 搭建 `RootTabs` + 两个 screen。
2. 完成 `SettingsForm` + `AsyncStorage` 持久化。
3. 接入 `llmClient.sendMessage`，打通对话闭环。
4. 完成 `MessageList` + `Composer` 交互和错误态。
5. 接入 `Live2DPanel(WebView)` 与失败重试。
6. 完成 toast、确认弹窗、空状态。

## 10. 验收清单（移动端）

- 能切换 `聊天/设置` 两个 Tab。
- 设置保存后重启 App 不丢失。
- 可完成至少一轮问答。
- API 失败可见错误消息，不崩溃。
- Live2D 加载失败不影响聊天。
